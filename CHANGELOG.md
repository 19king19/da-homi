# Changelog

## v2.2 (October 24, 2026)

Automatic updates, built on v2.1 without changing any v2.1 rule. A new script, scripts/update.py, checks a version manifest published at one stable URL and, when a newer version is out, downloads the package and swaps the install's files. The manifest and the download live behind the Hub's member gate, and the updater proves who it is with a member token (passed with --token or DA_HOMI_UPDATE_TOKEN, never printed). A download whose sha256 does not match the manifest is refused, and an unsigned package is refused unless --allow-unsigned is passed explicitly. Every apply backs the install up first, never overwrites the live DA_HOMI_MEMORY.md, and never touches da-homi-cache/. The target must look like a Da Homi install or the updater refuses it. Check exits 0 for up to date and 3 for update available; apply exits 0 for updated or already up to date, and 1 for any refusal, with nothing changed. The Hub operator's manifest format is in assets/update-manifest.example.json. This is how a private, Hub-gated skill updates without going public: authentication, not publicity, is what makes updates work.

## v2.1 (October 24, 2026)

Version 2.1 builds on the lighter v2 harness and changes nothing that v2 already did. Every v2 field, receipt rule, exit code, and test stays as it was, and the run receipt still says version 2, now with a features list beside it.

The first addition is pinning. fetch.py takes a pin option with a tag, a full commit SHA, or a short SHA of 7 to 39 hex characters. A tag is cloned with that tag and must name the commit checked out. A full SHA is fetched exactly, through an empty repository, a shallow fetch of that SHA, and a detached checkout, and it must equal the commit that arrives. A short SHA clones the default branch and must prefix its tip. A mismatch renames the fetch with a pin mismatch suffix, writes the manifest anyway with the pin unmatched, and exits 1. The verify option checks an existing fetch against a pin without cloning, and it exits 0 for a match, 1 for drift, and 2 when there is no fetch to check. An unpinned fetch behaves as before and prints the short SHA to pin next time. The manifest gains a pin record holding the requested ref, its kind, the resolved commit, and whether it matched.

The second addition is provenance. hub_search.py gains a provenance function that reports a candidate's age, last push, owner type, fork and archive status, license, stars, forks, and description, and raises the flags young, stale, fork, archived, no_license, thin, personal_account, and no_description, with dates_unknown in place of any guess. Every hunt candidate carries that record, and its flags print in brackets on the candidate line. The deep option on the hunt checks releases and contributors for the top five candidates and adds no_releases, single_contributor, or deep_unavailable. fetch.py copies a candidate's flags from the receipt into the manifest, counts the remote's tags, and adds no_tags when there are none. Flags never refuse a fetch, never change a score, and never change an exit code.

The third addition is host setup. The file assets/HOUSE.md gains a section for macOS and Linux that covers a separate dahomi user reached through a sudoers rule scoped to the Da Homi scripts, an egress allowlist for that user enforced by the packet filter with a logging proxy as the only way out, and secrets injected per call from the Keychain, a vault, or the Linux keyring instead of living in any environment.

The test suite adds pin tests against local git fixtures, unit tests for every provenance flag and its thresholds, hunt tests for provenance and the deep option with the GitHub API faked, and fetch tests for provenance in the manifest. No test touches the network.

Two pieces are held for a later pass by the owner's decision: the hard provenance floor, which would let a flag refuse a fetch or lower a score, and the canary planter. The standing exclusions also still hold, so there are no human gated installs, no scrubbed trials by default, no shape blocking, no static analyzer, no change to the excuse phrase list, and no receipt signing.
